improvement: **Hosts load only the system DLLs their Widgets use**: on Windows the Widget host no longer maps WINHTTP, SHELL32 (with Windows.Storage), Media Foundation or DirectComposition at startup; each loads the first time a Widget fetches, presents a GPU surface, and so on. A host running ten clocks loads 27 modules instead of 37 and holds about 0.5 MiB less private working set. If WINHTTP.dll cannot load, `wfetch` rejects with `FetchUnavailable: …` naming the DLL, function and Windows error.
